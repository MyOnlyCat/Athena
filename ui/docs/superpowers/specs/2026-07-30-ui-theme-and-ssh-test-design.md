# UI 可读性、双主题与 SSH 测试修复设计

## 目标

修复控制台现有的顶部登录人错位、输入提示与错误提示对比度不足、任务文案不准确和菜单分割线问题；新增可持久化的日间/夜间模式；修复首次信任 SSH 主机指纹后连接状态仍停留在“待确认指纹”的交互问题。

## 范围

### UI 样式

- 顶部栏用户名和角色信息保持两行展示，并在 64px 顶部栏内垂直居中。
- 用户名和角色文本使用各主题下清晰可读的前景色。
- 输入框正文、占位符、前后缀图标和禁用态在日间、夜间主题下均具有足够对比度。
- 错误 Alert 使用与背景有明确对比的错误文字、图标、边框和底色。
- 移除“当前任务”和“用户管理”之间的菜单分割线。

### UI 文案

- 侧边栏“发布任务”改为“当前任务”。
- 任务列表页标题“发布任务”改为“当前任务”。
- 首页“最近发布任务”改为“最近任务”，“暂无发布任务”改为“暂无任务”。
- API 内部实体名、路由、错误码和数据库字段保持不变，避免无关接口迁移。

### 日间与夜间模式

- 在顶栏用户区域前增加主题切换按钮。
- 首次访问且没有保存偏好时，使用系统 `prefers-color-scheme`。
- 用户主动切换后将 `light` 或 `dark` 保存到 `localStorage`。
- 刷新页面后恢复保存的主题。
- 使用 Ant Design `defaultAlgorithm` 和 `darkAlgorithm` 分别生成组件主题，并通过少量 CSS 变量覆盖项目自定义区域。
- 终端区域继续使用深色终端配色，不随页面主题切换，以保持命令行可读性。

## 组件边界

### ThemeProvider

新增独立主题上下文，负责：

- 读取系统主题和本地保存值；
- 向应用提供当前主题及切换方法；
- 生成当前 Ant Design `ThemeConfig`；
- 在文档根节点写入 `data-theme`，供自定义 CSS 使用。

该组件不处理登录状态、页面导航或业务请求。

### AppShell

负责：

- 渲染主题切换按钮；
- 修正顶部登录人区域布局；
- 更新菜单文案；
- 删除菜单分割项。

### 样式层

主题文件定义 Ant Design 令牌，自定义 CSS 通过语义变量表达背景、边框、正文、次要文字和卡片颜色。避免在组件中散落主题判断。

## SSH 测试数据流

当前真实服务器 `192.168.50.198:22` 已用现有 AsyncSSH 连接代码验证成功，因此服务器、端口、账号、密码和底层连接实现均不是本次故障根因。

首次测试的正确流程为：

1. UI 请求 `POST /hosts/{id}/test`。
2. API 成功连接并返回 `SSH_HOST_KEY_UNTRUSTED` 与指纹。
3. 用户确认指纹。
4. UI 等待 `POST /hosts/{id}/trust-fingerprint` 完成。
5. UI 再次请求 `POST /hosts/{id}/test`。
6. API 将状态更新为 `success`。
7. UI 显示“SSH 连接成功”，随后刷新主机列表。

若重新测试失败，UI 显示 API 返回的具体错误并刷新主机状态。指纹发生变化时仍需显式确认，不自动静默替换。

API 保留现有异常分类：

- `SSH_AUTH_FAILED`
- `SSH_TIMEOUT`
- `SSH_CONNECTION_FAILED`
- `SSH_HOST_KEY_UNTRUSTED`
- `SSH_HOST_KEY_CHANGED`
- `SSH_CONNECTED`

## 错误处理

- 信任指纹接口失败时不执行复测，直接显示标准 API 错误。
- 信任成功但复测失败时显示复测结果，主机列表同步失败状态。
- 主题偏好读取到非法值时忽略该值并回退到系统主题。
- `localStorage` 不可用时，主题切换在当前页面仍生效，不阻断应用。

## 测试策略

### UI 自动化测试

- 顶部登录人渲染用户名、角色和主题切换控件。
- 菜单包含“当前任务”，且“当前任务”和“用户管理”之间不存在分割项。
- 任务页和首页使用新的任务文案。
- 主题首次按系统偏好初始化，手动切换后持久化，刷新初始化时恢复保存值。
- SSH 首次返回未信任指纹时，确认后按“保存指纹 → 再次测试 → 刷新列表”的顺序执行。
- SSH 复测成功和失败分别显示对应消息。

### API 自动化测试

- 保留现有主机指纹与连接状态测试。
- 如调试中发现未覆盖的异常类型，再添加最小回归测试；不为已证实正常的底层连接代码制造无关改动。

### 完成前验证

- UI：定向 Vitest、完整 Vitest、ESLint、TypeScript 类型检查和生产构建。
- API：主机相关 Pytest、完整 Pytest、Ruff 和 MyPy。
- 集成：使用提供的服务器再次完成真实 SSH 连接，并验证指纹信任后的 UI/API 状态为成功。

## 非目标

- 不修改 SSH 凭据存储格式。
- 不修改任务 API、数据库实体或路由名称。
- 不重做整体导航信息架构。
- 不让网页终端随日间主题变成浅色。
- 不新增自动轮换或自动接受 SSH 指纹的行为。
