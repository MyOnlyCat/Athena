# Athena-Node 文件传输指南

网页终端右栏通过 SFTP 操作当前 SSH 主机。只有已确认主机指纹的服务器可进入
终端和文件管理；所有文件 HTTP 接口还要求本地 Bearer JWT。

## 路径导航

- 选择服务器后从 `/` 加载目录。
- 双击目录进入；非根目录显示 `..`，双击返回父目录。
- 当前路径显示为可点击的逐级目录，点击任一级可直接跳转。
- 可在路径框直接输入 POSIX 绝对路径并按 Enter。
- UI 只在目录请求成功后提交新路径。失败时保留原目录并把输入框恢复为已提交路径。
- 快速连续跳转时只接受最新请求结果，较早的成功或失败不会覆盖新路径。

远程路径必须以 `/` 开头且不能含空字节。上传目标目录在选择文件的瞬间固定；随后
切换路径不会改变已排队任务的目标位置。

## 文件操作

| 操作 | 本地 API | 行为 |
| --- | --- | --- |
| 列表 | `GET /api/v1/files/{host_id}/list?path=...` | 返回当前规范化绝对路径和条目 |
| 新建目录 | `POST /api/v1/files/{host_id}/directories` | 创建指定绝对路径 |
| 重命名 | `PATCH /api/v1/files/{host_id}/rename` | 同时提交源路径和目标路径 |
| 删除 | `DELETE /api/v1/files/{host_id}` | 文件删除；目录由 UI 请求递归删除 |
| 上传 | `POST /api/v1/files/{host_id}/upload?path=...` | 原始文件字节写入目标路径 |
| 下载 | `GET /api/v1/files/{host_id}/download?path=...` | 流式二进制响应 |

新建目录、重命名和删除成功后会重新加载当前目录。目录删除不可恢复，UI 会要求确认。

## 上传队列

文件选择器支持一次选择多个文件。每个任务依次经历：

`queued` → `uploading` → `completed`

也可能终止为 `failed` 或 `cancelled`。界面显示总进度、每个文件进度和状态。

- 最多同时上传 3 个文件；剩余任务保持 `queued`。
- 选择文件后自动打开可关闭的任务抽屉；关闭后进度变化不会再次弹出，可通过“任务”
  按钮重新查看。按钮角标只统计未完成任务。
- 单个任务失败后会释放并发槽，后续排队文件继续上传。
- 可取消单个 `queued`/`uploading` 任务，也可取消全部未完成任务。
- 已完成、失败或取消的任务可通过“清除已结束”统一移除。
- 取消活动任务会通过 `AbortController` 中止 HTTP 请求；取消排队任务不会发出请求。
- 切换主机或离开终端页面会中止所有活动请求，并使未完成队列失效。任务只保存在
  当前页面内，不会在刷新或重新进入后恢复。
- 上传成功会刷新当前目录；主机或路径已改变时，过期刷新结果会被忽略。

请求体为 `application/octet-stream` 原始字节，不是 multipart。服务端默认限制
单文件 1 GiB（`ATHENA_MAX_UPLOAD_BYTES`），超限返回 `FILE_TOO_LARGE`/413。
服务端直接以 `wb` 写入最终路径；网络中断或取消可能留下截断文件，应刷新目录并
手动删除或重新上传。

## 下载

服务端以 `application/octet-stream` 分块读取远程文件，并发送：

```text
Content-Disposition: attachment; filename="ascii-fallback"; filename*=UTF-8''...
```

UI 优先解析 RFC 5987 `filename*`，无效时回退到普通 `filename`，最后回退到
路径末段。完整响应被接收为 Blob 后触发浏览器保存，并立即撤销临时对象 URL。
下载失败会显示 API 错误，不会生成空文件。

## SSH 或断线排查

- 主机未出现在服务器列表：在 `/hosts` 测试 SSH 并明确确认当前
  `SHA256:` 指纹；指纹变更必须再次确认。
- 文件列表、上传或下载返回 `SSH_HOST_UNTRUSTED`：当前数据库没有可信指纹，
  先完成主机测试和确认。
- UI 显示 SSH 已关闭或文件请求失败：检查地址、端口、账号密码、防火墙及远端
  SFTP 权限，再在主机页运行连接测试。
- 断线后上传不会自动续传，下载也不会断点续传；重新连接后刷新目录，检查并清理
  截断文件，再重新执行传输。
- 远端权限或磁盘空间错误只会使对应上传任务 `failed`，不会阻塞其他排队文件。
