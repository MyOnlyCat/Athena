# Athena Node 快速开发启动脚本设计

## 目标

为 Windows 本地开发提供可双击运行的 `start-dev.cmd`，一次启动 Athena Node
API 与 UI，减少验证功能和页面前的手工准备步骤。

## 入口与文件

- `ui/start-dev.cmd`：用户双击的稳定入口。
- `ui/scripts/start-dev.ps1`：承载环境检查、依赖准备、进程启动和健康检查。

入口放在 `ui` 目录，因为当前开发工作区对 `ui` 和 `api` 可写；PowerShell 脚本通过
自身位置解析相邻的 `../api`，不依赖调用时的当前目录。

## 启动流程

1. 检查 `node`、`npm` 和 Python 3.12+ 是否可用，缺失时显示明确错误并保留窗口。
2. UI 缺少 `node_modules` 时执行 `npm ci`。
3. API 缺少 `.venv` 时创建虚拟环境，并在缺少项目包时执行
   `python -m pip install -e ".[dev]"`。
4. API 缺少 `data` 目录时自动创建，确保默认 SQLite 数据库可以首次落盘。
5. 为 API 子进程注入仅用于本地开发的配置：
   - 固定的 32 字符以上开发 JWT secret；
   - 有效的 44 字符 Fernet key；
   - 默认管理员账号 `admin`；
   - 默认管理员密码 `change-me-now`。
6. 在独立窗口启动 Uvicorn，监听 `127.0.0.1:8000`，启用自动重载。
7. 在独立窗口启动 Vite，监听 `0.0.0.0:5173`。
8. 轮询 API 健康接口和 UI 地址；两者就绪后打开
   `http://localhost:5173`。

开发配置只传给新启动的 API 进程，不创建或覆盖 `.env`。

## 端口与重复启动

- 若目标端口上的服务响应符合预期，视为已经启动并复用。
- 若端口被其他程序占用或服务在限定时间内未就绪，显示可操作的错误信息。
- 脚本不主动终止任何已有进程，避免误杀用户正在运行的服务。

## 错误处理

- 首次依赖安装失败时立即停止，并显示失败命令。
- API 或 UI 启动窗口保留原始日志，便于定位运行错误。
- 启动器失败时暂停窗口，确保双击运行时错误信息不会一闪而过。
- 正常启动后，关闭对应服务窗口即可停止该服务。

## 验证

- 对 PowerShell 脚本执行语法解析检查。
- 在依赖已存在的环境中运行启动器，验证 API 健康接口返回成功。
- 验证 UI 地址可访问，且 `/api` 代理能够访问 API。
- 检查重复运行不会启动重复服务或终止已有进程。
